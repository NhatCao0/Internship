AWS Weather Monitoring Architecture Guide

Step-by-step guide to building a serverless weather data pipeline and visualization system.

Introduction

This guide will guide through the process of setting up a robust, scalable, and cost-effective weather monitoring and visualization system on Amazon Web Services (AWS). We will leverage various AWS serverless services to build a fully automated data pipeline from data collection to interactive dashboards.

Step-by-Step Implementation

Step 1: AWS Account Setup and IAM Configuration

Before beginning, ensure you have an active AWS account. The first crucial step is to configure Identity and Access Management (IAM) roles and policies to grant necessary permissions to your AWS services while adhering to the principle of least privilege.

  • Create specific IAM Roles for your Lambda function, DynamoDB, and S3. These roles shng Architecture Diagrould only have the permissions required for their specific tasks (e.g., Lambda needs permissions to write to DynamoDB and S3, and to create CloudWatch logs).
  • **Best Practice:** Always apply the Principle of Least Privilege.

Step 2: Set up DynamoDB and S3 for Data Storage

Your weather data will be stored in two primary AWS services, each serving a distinct purpose:

Amazon DynamoDB (WeatherData Table)

  • Create a DynamoDB table named WeatherData.
  • Configure the primary key: location (Partition Key, String) and timestamp (Sort Key, String). This allows efficient querying of weather data by location and time.
  • Ensure encryption at rest is enabled (DynamoDB encrypts data by default).
  • DynamoDB will store near real-time weather data for quick access by your React dashboard.

Amazon S3 (weather-data-bucket)

  • Create an S3 bucket, for example, weather-data-bucket-saigon (bucket names must be globally unique).
  • This bucket will store raw and processed weather data as JSON or CSV files. It acts as a data lake for historical analysis and as the primary data source for AWS QuickSight.
  • We could also set up lifecycle policies to manage data storage costs (e.g., moving older data to S3 Glacier).

Step 3: Implement Lambda Function and EventBridge for Data Collection

This step involves setting up the core automation for collecting weather data.

AWS Lambda (WeatherDataCollector)

  • Write a Python Lambda function (e.g., lambda_weather_collector_s3.py) that:
    • Calls the Open-Meteo API to retrieve weather data.
    • Parses the JSON response.
    • Stores the processed data in your DynamoDB WeatherData table.
    • Stores the raw or processed data as JSON/CSV files in your S3 weather-data-bucket.
    • import json
import boto3
from datetime import datetime
from urllib import request, parse
from decimal import Decimal
import logging

logger = logging.getLogger()
logger.setLevel(logging.INFO)

dynamodb = boto3.resource('dynamodb')
table = dynamodb.Table('WeatherData')

s3 = boto3.client('s3')
bucket_name = 'weather-data-bucket-saigon'

# Custom JSON encoder
class DecimalEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, Decimal):
            return float(obj)
        return super(DecimalEncoder, self).default(obj)

def lambda_handler(event, context):
    try:
        latitude = 10.7769
        longitude = 106.7009

        api_url = "https://api.open-meteo.com/v1/forecast"
        params = {
            'latitude': latitude,
            'longitude': longitude,
            'current': 'temperature_2m,relative_humidity_2m,wind_speed_10m,wind_direction_10m,weather_code',
            'timezone': 'Asia/Bangkok',
            'forecast_days': 1
        }

        query_string = parse.urlencode(params)
        full_url = f"{api_url}?{query_string}"

        logger.info(f"Calling Open-Meteo API for coordinates: {latitude}, {longitude}")
        with request.urlopen(full_url, timeout=10) as resp:
            weather_data = json.loads(resp.read().decode())

        current_data = weather_data.get('current')
        if not current_data:
            raise ValueError("No 'current' data returned from API")

        def to_decimal(val):
            return Decimal(str(val)) if val is not None else None

        timestamp = datetime.utcnow().isoformat()

        item = {
            'location': f"{latitude},{longitude}",
            'timestamp': timestamp,
            'current_temperature': to_decimal(current_data.get('temperature_2m')),
            'current_humidity': to_decimal(current_data.get('relative_humidity_2m')),
            'current_wind_speed': to_decimal(current_data.get('wind_speed_10m')),
            'current_wind_direction': to_decimal(current_data.get('wind_direction_10m')),
            'weather_code': int(current_data.get('weather_code')) if current_data.get('weather_code') is not None else None,
            'data_source': 'open-meteo'
        }

        logger.info(f"Saving weather data to DynamoDB: {item}")
        table.put_item(Item=item)

        # 🔥 Save to S3
        s3_key = f"weather-data/{timestamp}.json"
        s3.put_object(
            Bucket=bucket_name,
            Key=s3_key,
            Body=json.dumps(item, cls=DecimalEncoder),
            ContentType='application/json'
        )

        return {
            'statusCode': 200,
            'body': json.dumps({
                'message': 'Weather data collected successfully',
                'timestamp': timestamp,
                'temperature': item['current_temperature'],
                'humidity': item['current_humidity'],
                'wind_speed': item['current_wind_speed']
            }, cls=DecimalEncoder)
        }

    except Exception as e:
        logger.error(f"Error: {str(e)}")
        return {
            'statusCode': 500,
            'body': json.dumps({
                'error': str(e)
            })
        }

Amazon EventBridge (Scheduled Rule)

  • Create an EventBridge rule (formerly CloudWatch Events).
  • Configure this rule to trigger your WeatherDataCollector Lambda function on a defined schedule (e.g., every 5 minutes, hourly, daily). This ensures automated and periodic data collection.

Step 5: Implement Monitoring and Security

Robust monitoring and security are paramount for any production-ready AWS solution.

Amazon CloudWatch (Logs, Metrics, Alarms, Dashboards)

  • **Logs:** Ensure all your Lambda functions and other services log their activities to CloudWatch Logs. Configure appropriate retention policies.
  • **Metrics:** Monitor key metrics for your services (e.g., Lambda invocations, errors, duration; DynamoDB throttled requests, consumed capacity).
  • **Alarms:** Set up CloudWatch Alarms to notify you of critical issues. For example, an alarm for Lambda errors > 0 or DynamoDB throttled requests > 0.
  • **Dashboards:** Create custom CloudWatch Dashboards to visualize the health and performance of your entire system at a glance.

Amazon SNS (Simple Notification Service)

  • Integrate SNS with CloudWatch Alarms to send notifications (e.g., email, SMS) when an alarm state is triggered.

AWS IAM (Identity and Access Management)

  • Continuously review and refine your IAM policies to ensure the Principle of Least Privilege is strictly followed.
  • Consider using AWS Secrets Manager or AWS Systems Manager Parameter Store for managing sensitive information like API keys, rather than hardcoding them.
  • Ensure data is encrypted at rest (DynamoDB, S3) and in transit (HTTPS/SSL/TLS for all communication).
